# Claudius

Just because you have to use a coding agent at work doesn't mean you can't be silly about it. Claudius is a Claude Code plugin that gives every session a randomly chosen persona: a noir detective, a Whitman-esque poet, a NASA flight controller, a caveman fresh out of the glacier, and about forty more.

## Install

From GitHub:

```bash
claude plugin marketplace add x-kej/claudius
claude plugin install claudius@claudius
```

Or from a local clone, which is better if you plan to edit personas, since a plugin from a local marketplace loads straight from your folder:

```bash
git clone https://github.com/x-kej/claudius ~/code/claudius
claude plugin marketplace add ~/code/claudius
claude plugin install claudius@claudius
```

You can also do this from inside a Claude Code session with the same commands as slash commands: `/plugin marketplace add …`, then `/plugin install claudius@claudius`. Or use the `/plugin` menu. Either way, the persona takes effect from the next session you start.

Both routes add the marketplace and the plugin to your user `settings.json` (`extraKnownMarketplaces` and `enabledPlugins`). If that file is generated by a dotfile manager such as chezmoi, add those two entries to its source too, or the next apply will remove them. Running the install commands first and then diffing the live file against your source is an easy way to get the exact JSON.

### Upgrading from the hooks-only version

Earlier versions were wired up as two hooks in `~/.claude/settings.json` pointing at `claudius.sh`. Remove both of those hook entries when you install the plugin, before starting another session. If you don't, sessions get a persona from each.

If you install from a local clone that still has the old `weights.csv` in it, your weights are copied into the plugin's data directory the first time it runs. A GitHub install starts with fresh weights.

## How it works

The persona is delivered as an [output style](https://code.claude.com/docs/en/output-styles), Claude Code's built-in mechanism for setting a session's voice, instead of as hook output.

1. When a session starts, the plugin's `SessionStart` hook draws a persona and writes it to `output-styles/persona.md`.
2. Claude Code reads the plugin's output style after that hook has run, and the style arrives with the first prompt. So the session gets the persona just written.
3. A `UserPromptSubmit` hook adds a short reminder of that persona's voice every few prompts.

The style sets `force-for-plugin: true`, so it applies whenever the plugin is enabled, without an `outputStyle` setting. It also sets `keep-coding-instructions: true`, so Claude keeps its normal software-engineering instructions.

Each draw is logged to `picks.log` in the plugin's data directory, one line per session: time, session id, persona.

A few consequences of the style being a single shared file:

- If a second session starts before the first one has had its first turn, both end up with the same persona, the one written last. On each session's first prompt, the reminder hook re-reads the style file, so each session's reminders still match the voice it actually loaded.
- `/reload-plugins` re-reads the style file, so it can switch a running session to whatever persona a later session wrote.
- Resuming an old session (`claude --resume`) doesn't draw a new persona. It gets whatever the style file holds.

## Configuration

### Persona weights

Picks are weighted to keep recent personas from repeating. The weights live in the plugin's data directory, `~/.claude/plugins/data/claudius-claudius/weights.csv`, one row per persona: `<name>,<preference>,<weight>`.

- The weight is what's actually used to pick. Higher means more likely.
- Each time a persona isn't picked, its weight grows by its preference. When it is picked, its weight resets to its preference. A preference of `1`, the default, gives an even rotation. Raise it for a persona you want more often, or lower it for a rare treat.
- Set a weight to `0` to take that persona out of the rotation. It stays at `0` until you change it.

### Reminder frequency

The reminder fires every 4 prompts. To change that, set `CLAUDIUS_REMIND_EVERY` in the `env` block of your Claude Code settings. Set it to `0` to turn reminders off and rely on the output style alone.

## Writing personas

Each persona is a Markdown file in `personas/`. New files join the rotation automatically. The format:

```markdown
---
reminder: A one-line cue for the mid-session reminder. Name concrete material, like the address term, a few signature words, and the signature move.
---

You ARE … (who the persona is, in a sentence or two)

**Address:** how the persona speaks to the user.

**Frame:** what the work becomes in the persona's world. What reading files, running tests, editing, a bug, a pass, a failure, and a clean build are called.

**Moves:** one to three sentence shapes or structural devices that make the voice recognizable at a glance.

**Lexicon:** fifteen to twenty words and phrases in the register.

**Sample:**
> Two to four sentences of a routine technical moment in the voice, with real-looking paths and numbers.

**Emoji:** a handful that fit.
```

The sample and the lexicon do most of the work. Claude imitates examples much more reliably than it follows descriptions of a tone. `common.md` holds the rules every persona shares, and it's appended to each one.

Every new session draws a fresh persona and overwrites `output-styles/persona.md`, so the way to try a particular persona while tuning it is through the weights. Temporarily set every other persona's weight to `0`.

## Running without the plugin

`claudius.sh` still works as a plain `SessionStart` hook in `settings.json`, without the plugin. In that mode it prints a persona as session context, with no output style, and keeps its state in `.state/` in the repo. The reminder hook is `claudius.sh --remind`.
